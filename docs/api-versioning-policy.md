1 breaking changes
Removing a response field.
Renaming a field (for example, changing Title to CourseTitle).
Changing HTTP status codes returned by an endpoint.
changing validation rules.
Changing the default sort order of results.
Changing the structure of a response.
2 additive (non-breaking) changes
Adding a new optional response field.
Adding a completely new endpoint.
Adding an optional query parameter.
Adding additional links to a HATEOAS response.
3 sunset window
When a new major API version is released, the previous version will continue to be supported for at least six months.
This allows rural training centres and other clients operating on quarterly maintenance schedules sufficient time to migrate.
4 communication
Beginning on the day V2 is released, TMS will communicate the deprecation of V1 using multiple channels.
5 Skipping versions
V1 → V3 is allowed clients are not forced to migrate
through every intermediate version
